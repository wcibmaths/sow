My Week Build Steps
WCIB Maths · SoW tracker

Building the two My Week changes in Replit

Seven steps. Four of them are text to copy and paste — two prompts for the Replit Agent, one Firestore rule, and a field you add by hand in Firebase. Do them in order; step 4 must be done before step 5 or the reminders won’t save.

Before you start Your index.html is over 5,800 lines. Replit Agent will happily rewrite a file that size and quietly break something, so both prompts below tell it exactly which files it may touch. Don’t remove those lines when you paste.

In Replit

Prompt 1 — stop the week shifting

Paste into Replit Agent

This is the fix for what happened on Thursday. It makes the tracker record which lesson you taught in which slot, instead of working it out fresh every time.

Prompt 1 · pinning fix
In this project, only edit my-week.js. Do not reformat, restructure or rewrite index.html — the one exception is the single line in point 6 below. If any other change to index.html seems necessary, stop and tell me first.

THE PROBLEM
In my-week.js, mwAssignments() decides which lesson sits in which timetable slot by finding the first lesson whose status is not "Done" (lessons.findIndex(l => getStatus(l.id,set) !== 'Done')) and then counting back over the slots earlier in the week (s.day < currentInfo.day). Today's own slots are not counted, so the moment a teacher marks today's lesson "Done" the pointer moves forward and the entire week's row shifts by one lesson: Monday takes Tuesday's lesson and today's cell jumps to a lesson that has not been taught. Nothing records what was actually taught when, so past weeks are reconstructed rather than remembered.

THE FIX
Record the lesson against the slot, and lay the week out from those records.

1. STORAGE. Use the existing shared Firestore document (window.WCIB_DB, which is sow/progress). Add one new top-level map field called "taught". Key each entry as:
   TEACHER__YG-SET__YYYY-MM-DD__Pn
   for example SSW__9-Ma4__2026-09-24__P2
   The value is the lesson id string, for example "y9_13".
   Write it with doc.set({ taught: { [key]: lessonId } }, { merge: true }) so nothing else in the document is disturbed. To clear one, write firebase.firestore.FieldValue.delete() for that key.
   Read "taught" inside the existing mwListen() snapshot handler alongside "resources", hold it in a module-level variable, and re-render when it changes.

2. DATES. Build each slot's date from info.monday plus slot.day, and format it YYYY-MM-DD from the local date parts (getFullYear, getMonth()+1, getDate(), zero-padded). Do NOT use toISOString() — this site is used in UTC+7 and that would record the wrong day.

3. PIN WHEN A STATUS IS SET. In the change listener at the bottom of the file (the one for [data-mw-status]), after setStatusValue(...):
   - "Done", "In progress" or "N/A" writes the taught record for that slot.
   - "Not started" deletes the taught record for that slot.

4. LAY THE WEEK OUT FROM THE RECORDS. Rewrite the per-class loop inside mwAssignments() as follows:
   - Build this class's ordered list of slots for the week being displayed.
   - For each slot, if "taught" holds a record and that lesson id exists in this class's lesson list, that slot's lesson is fixed.
   - Walk the slots forwards. After a fixed slot the cursor becomes that lesson's index + 1, except when that lesson's status is "In progress", where the cursor stays on the same index so the next slot repeats the same lesson — a lesson carried over into the next period. Slots that are not fixed take the cursor and advance it by one.
   - Then walk backwards and fill any unfixed slots that come before the first fixed one: each takes the index of the slot after it, minus one.
   - If a week has no records at all (a future week, or any week before this feature existed), fall back to the current behaviour: first lesson not marked "Done", counted back over the earlier slots.
   - Keep the existing beforeStart handling for indexes below zero, and keep the existing "No remaining SoW lesson" message.

5. SHOW IT. When a slot's lesson comes from a record, add a short line under the status dropdown reading "Pinned · taught Thu 24 Sep" (the slot's own date). Reuse the existing .mw-slot class for its styling so no new CSS is needed anywhere.

6. ONE EXISTING BUG. In index.html, inside syncFromServer(), the first-run write window.WCIB_DB.set(_toDoc(local)) has no merge option and would erase "resources" and "taught". Change that one call to window.WCIB_DB.set(_toDoc(local), { merge: true }). This is the only edit to index.html.

Do not change the timetable data, mwClassFor, the Slides and Practice Qs link feature, the progress ticks, or the sign-in.

When it finishes, read its summary. If it says it changed anything in index.html beyond that one merge line, tell it to undo that part before you go on.

Test the fix in the preview

In Replit
  1. Open the preview, go to My Week, sign in and pick your own initials.
  2. Set one of today’s lessons to Done. Nothing else in that row should move — only the next slot for that class rolls on to the next lesson.
  3. Reload the page. The lesson should still be sitting in the slot you taught it in.
  4. Set the same slot to In progress. The next slot for that class should now repeat the same lesson.
  5. Set it back to Not started. The pin should disappear and the week should go back to how it was.
  6. Click the back arrow to last week. It should stay put now instead of redrawing when you tick something.

If anything is wrong, tell the Agent what you saw rather than starting over — it still has the context.

5

Make the reminders genuinely private

Firebase console → Firestore → Rules

Hiding the panel in the browser isn’t privacy — anyone who knows where to look could still read the data. This rule is what actually stops it. A teacher can read and write only the document named after their own signed-in email.

Don’t replace the whole rules file. Paste this block inside the existing match /databases/{database}/documents { … } section, just before its closing brace, leaving your current rules for sow and teachers exactly as they are. Then click Publish.
Firestore rule · add, don’t replace
// Private reminders — each teacher reads and writes only their own.
match /notes/{email} {
  allow read, write: if request.auth != null
    && request.auth.token.email != null
    && request.auth.token.email.lower() == email;
}
6

Prompt 2 — the reminders panel

Paste into Replit Agent

Almost all of this goes into a new file, so there is very little to go wrong in index.html.

Prompt 2 · private reminders
Add a private reminders panel to the My Week page.

FILES
Put all new code in a NEW file called notes.js. In index.html you may make exactly three changes and nothing else:
  a) one new line <script src="./notes.js"></script> immediately after the existing <script src="./my-week.js"></script> line;
  b) one empty container <div id="mw-notes"></div> directly after <div id="mw-content"></div> inside <div id="view-week">;
  c) the few lines described in point 1 below.
Do not reformat or restructure index.html in any other way.

WHO SEES WHAT
Reminders are private to each teacher. A teacher sees their own and nobody else's, including the head of department. I have already added a "code" field holding each teacher's initials (SSW, FTA, MKM, HPA, ADE, XLN) to the documents in the teachers collection, and published a Firestore rule allowing each signed-in teacher to read and write only notes/<their own email>.

1. KNOWING WHO IS SIGNED IN. The sign-in block in index.html already looks the user up with firebase.firestore().collection('teachers').doc(email.toLowerCase()).get() inside checkAllowed(). In that same function, when the document exists, also set:
   window.WCIB_ME = { email: <the signed-in email, lower case>, code: <the document's code field, or null> };
   and then call window.WCIB_NOTES_REFRESH && window.WCIB_NOTES_REFRESH();
   When nobody is signed in or the address is not on the list, set window.WCIB_ME = null and call the same refresh. Keep this to those few lines.

2. STORAGE. A separate Firestore collection called notes, one document per teacher, the document id being the signed-in email in lower case. Shape:
   { items: [ { id, text, colour, done, created, updated } ] }
   colour is "amber", "teal" or "grey"; done is a boolean; created and updated are millisecond timestamps.
   Only ever read and write notes/<my own email>. Never query the notes collection as a whole, and never touch another teacher's document. Use onSnapshot on that single document so a teacher's reminders stay in sync across their laptop and phone.

3. WHEN THE PANEL SHOWS. Re-check all of this whenever the #mw-teacher dropdown changes and whenever the sign-in state changes:
   - Not signed in: one muted line, "Sign in with your school email to use your reminders." No input, no Firestore call.
   - Signed in, and the Teacher dropdown is set to my own code: the full panel.
   - Signed in, but the dropdown is set to another teacher: hide the panel and show one muted line, "Reminders are private to each teacher." Make no Firestore call at all.

4. THE PANEL. A heading "My reminders", the number of unticked items, and a collapse/expand control that remembers its state in localStorage (wrap every localStorage call in try/catch).
   - An input with placeholder "Add a reminder…", maximum 160 characters, three colour swatches (amber, teal, grey) and an Add button. Pressing Enter also adds.
   - Each reminder shows a tickbox, the text, "Added <weekday and date>", an Edit button that edits in place (Enter or Save commits) and a Delete button.
   - Ticked reminders stay in the list, struck through and greyed, until deleted. A "Clear ticked" button deletes only those.
   - Reminders never expire, never reset at the start of a week, and are only ever removed by the teacher.
   - Empty state: "Nothing here yet."

5. STYLE. Match the existing My Week look exactly: Poppins, the teal palette already used by .mw-pill and .mw-popover, small radii, no purple, no emoji. Inject the CSS from notes.js as a <style> element at load so index.html is not touched for styling.

6. ERRORS. Handle Firestore failures the way my-week.js already does — a small message inside the panel, never an alert() and never a silent failure.

Do not change the week grid, the timetable data, the progress ticks, or the sign-in logic beyond point 1.

Test the privacy, then publish

Replit, then GitHub
  1. Signed out, My Week should offer the sign-in line and nothing else.
  2. Signed in as yourself with the dropdown on SSW: add a reminder, edit it, tick it, delete one.
  3. Switch the Teacher dropdown to a colleague. The panel must disappear and say reminders are private.
  4. Open the preview on your phone and sign in. Your reminders should already be there.
  5. Ask one colleague to sign in and confirm they see their own empty panel, not yours. This is the test that matters — if they can see yours, the rule in step 5 didn’t publish.
  6. When it all works: commit and push to GitHub. GitHub Pages rebuilds wcibmaths.github.io/sow in a minute or two. Hard-refresh the live site (Ctrl/Cmd + Shift + R) before deciding anything is wrong.

If the Agent goes off the rails

Don’t try to talk it back into shape across several messages — that’s how the file gets worse. Open History in Replit, restore the checkpoint from step 1, and paste the prompt again with one sentence at the top saying what it did wrong last time.

If the reminders panel appears but nothing saves, it is almost always the rule in step 5: open the browser console, and a red “Missing or insufficient permissions” line confirms it. Re-check that the rule was published and that you’re signed in with the same address that’s in the teachers collection.

One thing to decide later, not now Once lessons are pinned, past weeks become a real record, so the back arrow could usefully go further than one week — it’s currently capped at one. Worth doing after a few weeks of real data, when there’s something to look back at.
