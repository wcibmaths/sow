Fix “Missing or insufficient permissions”

Prompt 1 · permissions fix
Fix a permissions bug in notes.js. Only edit notes.js — do not touch index.html, my-week.js or any other file.

THE BUG
The reminders panel shows "Could not load reminders from Firestore: Missing or insufficient permissions." notes.js uses the signed-in EMAIL ADDRESS as the Firestore document id, so it reads and writes notes/<email>. The published security rule only allows notes/<teacher code> — for example notes/SSW — and checks it against the "code" field on that teacher's document in the teachers collection. So every read and every write is denied.

THE FIX
Use window.WCIB_ME.code as the document id everywhere notes.js currently uses the email. In the current file that is five places:

1. In refresh(), change
     const me=owner(), next=me?.email||null;
   to
     const me=owner(), next=me?.code||null;

2. In update(), change
     if(!me || me.email!==state.identity || state.saving || state.loading) return false;
     const identity=me.email;
   to
     if(!me || me.code!==state.identity || state.saving || state.loading) return false;
     const identity=me.code;

3. In the [data-mn-add] submit handler, change
     const identity=owner()?.email;
   to
     const identity=owner()?.code;
   and change
     if(success && owner()?.email===identity)
   to
     if(success && owner()?.code===identity)

4. In the [data-mn-edit] submit handler, make those same two changes: owner()?.email becomes owner()?.code in both places.

AFTERWARDS
state.identity now holds the teacher code, and firebase.firestore().collection('notes').doc(...) is called with the code. Search notes.js for ".email" and confirm the only remaining use is inside owner(), where window.WCIB_ME.email is compared against the signed-in user's email — that check is correct and must stay exactly as it is.

Change nothing else: not owner(), not the privacy states, not the Firestore transaction logic, not the error handling.

Then check

  1. Push to GitHub, hard-refresh the live site (Ctrl/Cmd + Shift + R), open My Week with the teacher set to SSW.
  2. The red permissions error should be gone. Add a reminder — it should appear and survive a reload.
  3. In Firebase → Firestore → Data you should now see a notes collection with a single document called SSW.
Once that works, ask a colleague to sign in. If they see their own empty panel and not yours, open notes.js and change isolationTestConfirmed=false on line 6 to true. That removes the pink “Privacy check pending” banner. I already tested the rule four ways in the Firebase playground — you allowed, Marcin denied, signed-out denied, your gmail allowed — so this is confirmation rather than discovery.

Prompt 2 · sticky note redesign
Redesign the reminders panel in notes.js as sticky notes, and move it above the week grid.

FILES
- index.html: exactly one change. Move the existing line <div id="mw-notes"></div> so it sits immediately BEFORE <div id="mw-content"></div> inside <div id="view-week">, instead of after it. Change nothing else in index.html.
- notes.js: everything else. Keep the Firestore logic, the owner() privacy check, the state machine, the collapse behaviour and the error handling exactly as they are. This is a presentation change only.

LAYOUT
The panel sits between the My Week heading and the timetable, in a band with background #F9F5EE, a 1px #E2DDD7 border, 12px radius, and 18px of space below it before the grid.

Band header in one row: the title "My reminders" at 13.5px/600 with a muted count beside it ("3 to do", or "all done", or nothing when the list is empty); on the right, the four colour swatches that set the colour of the next new note, then the "Clear ticked" button.

Below the header, a horizontal rail of notes: display:flex, 13px gap, overflow-x:auto, so a long list scrolls sideways instead of pushing the timetable down the page. On a phone that becomes a swipe.

THE NOTES
Each note is 164px wide, min-height 150px, 3px radius (nearly square — it is paper, not a card), padding 15px 14px 13px, shadow 0 1px 2px rgba(47,54,64,.06), 0 6px 16px -8px rgba(47,54,64,.28). Give each one a turned-up bottom-right corner using a ::after triangle: 20px square, background linear-gradient(135deg, transparent 50%, rgba(0,0,0,.09) 50%).

Rotate each note very slightly, between -0.7deg and +0.7deg, derived from its id so the angle is stable across re-renders. On hover lift it: translateY(-3px), rotate(0deg), and a deeper shadow.

Four colours — background then text:
  butter  #F7E9B0 / #6B5A1E
  blush   #F3DCD7 / #9C5B4B
  mint    #DCEFE3 / #3F7C61
  blue    #DCE7F0 / #4F7290
Replace the current amber/teal/grey set with these four everywhere, including the swatches and the stored colour values. When reading from Firestore, map an existing note with colour "amber" to butter, "teal" to mint and "grey" to blue, so reminders saved before this change still display correctly.

The text is the main element of the note: font 600 14.5px/1.45 Inter, letter-spacing -.01em, flex:1, overflow-wrap:anywhere. It is edited in place with contenteditable — remove the separate Edit button and the edit form entirely. Save on blur and on Enter (preventDefault so Enter does not insert a line break). Keep the 160-character limit.

Bottom row of each note: the added date on the left at 10.5px, opacity .72; on the right a small delete button (✕, 22px square, background rgba(255,255,255,.55), 5px radius) that is opacity:0 by default and becomes visible on hover or when anything inside the note has keyboard focus.

Top right of each note: a 19px round tick button with a 1.6px border in the note's own text colour at .4 opacity, empty until ticked. When ticked it fills with that text colour and shows a tick drawn in the note's background colour; the whole note drops to opacity .6 and the text gets a line-through. Ticked notes stay in the rail until deleted or cleared.

Last in the rail, an "add" tile the same size as a note: 2px dashed #E2DDD7 border, transparent background, a large + above the words "New reminder", centred, muted text. Clicking it creates an empty note in the currently selected swatch colour and puts the cursor straight into it.

TYPE
Use Inter, the site font, for the note text — not a handwriting font.

ACCESSIBILITY
Keep everything keyboard reachable. The tick, the delete and the add tile are real buttons with aria-labels; the editable text has role="textbox" and an aria-label. Keep the existing three privacy states in render() word for word, along with the loading and error messages.

Prompt 3 · pill colours
Change the Slides / Practice Qs pill colours in index.html. This is three CSS rules and nothing else — do not touch any JavaScript, any markup, or any other style.

WHY
These pills were never moved onto the site's current palette. They still use the old teal, which against the cream page looks nearly the same whether ticked or not.

Find these rules, which sit together around line 681 of index.html:

  .mw-pill{font:500 10px Poppins,Arial,sans-serif;border:1px solid #bfd6d3;background:#f4faf9;color:#257474; ...}
  .mw-pill.filled{border-color:#2b8581;background:#d7eeea;color:#165f5c}
  .mw-link-chip{font:500 10px Poppins,Arial,sans-serif;border:1px solid #bfd6d3;border-left:0;background:#eaf4f2;color:#195f61; ...}

Change ONLY the font, border, background and colour values in them. Keep every other property — border-radius, padding, cursor, display, align-items, gap — exactly as it is:

  .mw-pill        font:500 10px Inter,'Segoe UI',Arial,sans-serif;  border:1px solid #E2DDD7;  background:#FFFFFF;  color:#6C7480;
  .mw-pill.filled border-color:#5A9B7F;  background:#C9E4D4;  color:#3E7358;  font-weight:600;
  .mw-link-chip   font:500 10px Inter,'Segoe UI',Arial,sans-serif;  border:1px solid #E2DDD7;  border-left:0;  background:#F9F5EE;  color:#6C7480;

Leave the .mw-past overrides directly below them exactly as they are — past days should still grey out.

The result: an unticked pill is plain white with grey text, a ticked one is filled mint with dark green text, and the difference is obvious at a glance. The font change from Poppins to Inter is deliberate — the rest of the site moved to Inter and these pills were left behind.
